## 3. P0 代码与关键逻辑

### 顾客进入与资料锁定

- 顾客端不再显示微信登录界面：打开页面自动调用 `POST /api/auth/login`
- 自动进入固定带 `localOnly: true`，服务端只创建/恢复本机账号，不跳微信授权
- 统一登录接口的返回：
  - `localOnly` 或未配置公众号：`{ mode: 'local', token, user }`
  - 非 `localOnly` 且公众号已激活、在微信内：`{ mode: 'wechat', redirectUrl }`（保留能力，顾客端当前不调用）
- `POST /api/auth/profile`：首次设置昵称、头像、手机号；之后再次提交返回 409
- `data/users.json` 保存账号和 token；token 通过 `x-user-token` 请求头传递
- 一个手机号只能绑定一个账号，保证按手机号发券精准
- 公众号授权代码全部在独立模块中：
  - `lib/wechat-auth.js`：读取 `wechat.appId/appSecret/enabled`、生成授权地址、校验 state、code 换 openid、预填用户资料、生成一次性登录码
  - `routes/wechat-auth.js`：`/api/auth/wechat/start`、`/api/auth/wechat/callback`、`/api/auth/exchange`
  - 未启用时模块 `enabled=false`，不发起网络请求、不校验配置、不打印配置状态；OAuth 路由直接回到首页
  - 当前实现没有使用微信长效 access_token，也没有单独的 token 刷新流程；本次只做代码收敛，未新增功能

### 点餐搜索与推荐

- 顾客端搜索栏按菜名、分类、标签、描述实时过滤；搜索时隐藏分类和推荐区
- `GET /api/menu` 增加 `recommendations`：
  - `recent`：当前登录账号最近 6 个不同菜品，已取消订单不计入
  - `popular`：所有未取消订单按菜品数量汇总的前 6 个热销菜品，并排除本人最近点过的菜品
  - 已下架、售罄菜品不会进入推荐
- 推荐区只展示在「全部」分类、无搜索词时；「最近点过」「销量较高」横向滑动，可直接加购物车

### 商家菜品搜索

- 「菜品管理」增加搜索栏，按菜名、分类、标签、描述过滤
- 搜索结果仍按分类分组；没有结果时显示空状态
- 搜索不改变菜品数据，只影响当前列表展示

### 服务端算价与配送费

- `normalizeOrderItems()`：只接收 `{ id, count }`，按 `menu.json` 当前价格计算
- `normalizeOrderInfo()`：校验收货人、11 位手机号、地址、可选坐标
- `createOrder()`：
  - `subtotalCents` = 各菜品单价 × 数量
  - `deliveryFeeCents` = `subtotal >= 5000 ? 0 : 300`
  - `discountCents` = 优惠券金额
  - `totalCents = subtotal + deliveryFee - discount`
- 客户端伪造价格、配送费、总额均无效

### 自动定位

- 浏览器 `navigator.geolocation` 获取 WGS84 坐标
- 服务端 `/api/geocode`：
  - 配置 `amapKey` 时，先 WGS84 → GCJ-02，再调高德逆地理编码
  - 未配置或高德失败时，尝试 OpenStreetMap Nominatim
  - 两者都失败返回 502，前端提示手动填写
- 订单保存 `location: { lat, lng }`；商家详情可打开高德地图导航
- 定位需要 HTTPS 或 localhost；HTTP 局域网下手机浏览器可能直接拒绝

### 优惠券按手机号发放

- `POST /api/admin/coupons/issue` 接收 `{ templateId, phone }`
- 服务端只查找 `phone` 完全一致且已完成资料的账号
- 找不到账号返回 404，不会误发给其他顾客
- 同一账号已有同款未使用券时不重复发放
- 发放记录显示昵称和手机号

### 订单详情

- `GET /api/admin/orders` 已返回完整字段：顾客账号、收货人、电话、地址、坐标、备注、菜品、商品小计、配送费、优惠、合计
- 商家点击订单卡片，前端打开 `#orderDetailOverlay` 详情弹窗
- 详情内同样可以接单、完成、取消
- 轮询刷新时如果详情弹窗开着，会同步更新状态

### 订单并发写入

- `saveJson()` 先写 `.tmp` 再 `rename`
- Node 单进程同步写入，两个请求不会同时写同一份文件
- 下单时先扣券再写订单；任一步失败会回滚
- `test/smoke.js` 用 10 个并发请求验证订单 id、取单号和 JSON 内容都不丢

## 4. 商家使用说明

1. 修改 `config.json`：口令、店名、电话、营业时间、配送费、满免门槛
2. 建议配置 `amapKey`，让顾客能一键定位
3. 执行 `npm install`，再执行 `node server.js`
4. 打开 `/admin`，输入口令登录
5. 进「菜品管理」核对 47 道菜价格，按需改价、上新、售罄、上下架
6. 进「优惠券」确认新人券，按需新增或调整
7. 发券时在「发放优惠券」填写顾客登录绑定的手机号
8. 营业时保持 `/admin` 订单页打开、设备音量开启
9. 顾客下单后点订单卡片查看完整配送信息，再「接单」→「出餐完成」；待接单/制作中可取消并退券
10. 每天营业结束备份 `data/` 和 `config.json`

- 菜品改价/上新/售罄/上下架
